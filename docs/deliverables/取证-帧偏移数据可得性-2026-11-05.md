## ① `.wzl/.wil` 的帧结构里有没有偏移字段

### 1.1 权威结构定义（C++ 参考客户端，第二来源）

> 本小节所有 `client/reference_full/**` 的行号统一标 **`@412fe3e8`**（GodM2 仓 HEAD，见 §0.2），下文不再逐行重复。

`client/reference_full/Classes/Wil/WIL.h:50-56@412fe3e8`（GB18030 编码，`#pragma pack(2)`）：

```c
typedef struct TDXTextureInfo
{
    unsigned short nWidth;
    unsigned short nHeight;
    short px;          // ← X 偏移
    short py;          // ← Y 偏移
}*pTDXTextureInfo;
```

⇒ 帧头 = **8 字节**：`w u16 @0..2`、`h u16 @2..4`、**`px i16 @4..6`**、**`py i16 @6..8`**。

同文件 `WIL.h:18-37` 的 `TDXTextureSurface` 把这两枚值缓存成 `short nPx; //x` / `short nPy; //y`（`:23-24`）。

新格式多一个 `nSize`：`client/reference_full/Classes/Wil/wmM2Def.h:13-17` 的
`typedef struct TWMImageInfo { TDXTextureInfo DXInfo; int nSize; }`（`#pragma pack(1)` ⇒ **12 字节**）。
C++ 读取时按 `m_FNewFmt ? sizeof(imginfo) : sizeof(imginfo) - 4` 分档
（`client/reference_full/Classes/Wil/wmM2Def.cpp:342`）—— 老格式只读前 8 字节，正是 `DXInfo`。

### 1.2 WIL/WIX（`tools/wil2atlas/src/wil_decoder.rs@412fe3e8`）

**WIL 文件头 60 字节**（`wil_decoder.rs:505-515`，与 `WIL.h:39-48` 的 `TWMImageHeader` 逐字段对应）：

| 偏移 | 宽 | 字段 | 类型 | 说明 | 出处 |
|---:|---:|---|---|---|---|
| 0 | 1 | `flag` | u8 | `0x19` 普通 / `0xFF` 加密 / `0xFE` 变体 | `:507` |
| 1 | 39 | `title[39]` | char[] | 标题（首个 NUL 截断） | `:508` |
| 40 | 4 | `password` | i32 | 口令（`0xFF` 时与帧数异或） | `:509` |
| 44 | 4 | `image_count` | i32 | 声明帧数 | `:510` |
| 48 | 4 | `color_count` | i32 | `0x100`=8bit / `0x10000`=16bit / `0xFFFFFFFF`=32bit | `:511` |
| 52 | 4 | `palette_size` | i32 | 样本 1024 | `:512` |
| 56 | 4 | `index_offset` | i32 | **0 = 老格式**（帧头 8 B）；非 0 = 新格式（12 B） | `:513` |

**WIX 索引头 48 字节**（`wil_decoder.rs:536-589`）：`Title[41] @0..41` + `bitCount[3] @41..44` + `IndexCount i32 @44..48`，偏移数组自 `48` 起、每项 i32、按口令异或（`:565`、`:584-587`）。

**★ 帧头 —— 这就是答案所在**（`wil_decoder.rs:206-209`）：

| 帧内偏移 | 宽 | 字段 | 类型 | 语义 | 出处 |
|---:|---:|---|---|---|---|
| 0 | 2 | `width` | u16 LE | 帧宽 | `:206` |
| 2 | 2 | `height` | u16 LE | 帧高 | `:207` |
| **4** | **2** | **`px`** | **i16 LE** | **锚点 X（= C++ `TDXTextureInfo.px`）** | **`:208`** |
| **6** | **2** | **`py`** | **i16 LE** | **锚点 Y（= C++ `TDXTextureInfo.py`）** | **`:209`** |

⇒ **有 X/Y 偏移字段**。字段名在本仓叫 `px` / `py`，注释明写「对应 C++ TDXTextureInfo.px/py」（`wil_decoder.rs:49-52`）。

### 1.3 WZL/WZX（`tools/wil2atlas/src/wzl_decoder.rs@412fe3e8`）

- `.wzx`（索引）：`0x00..0x2B` 保留区、**`0x2C` u32 帧数 count**、`0x30` 起 `count × u32` 偏移（`:96-108`）；文件大小 = `48 + count*4`。
- `.wzl`（数据）：`0x00..0x3F` **64 字节头**，数据区自 `0x40`（`WZL_DATA_START`，`:57`）。

**★ 每帧块头 16 字节**（`wzl_decoder.rs:264-269`）：

| 块内偏移 | 宽 | 字段 | 类型 | 语义 | 出处 |
|---:|---:|---|---|---|---|
| 0 | 2 | `marker` | u16 LE | 低字节 `0x03`=8bit / `0x05`=16bit（`:272-276`） | `:264` |
| 2 | 2 | — | u16 | 未用，实测 0 | `:21`（文档） |
| 4 | 2 | `w` | u16 LE | 帧宽 | `:265` |
| 6 | 2 | `h` | u16 LE | 帧高 | `:266` |
| **8** | **2** | **`px`** | **i16 LE** | **锚点 X** | **`:267`** |
| **10** | **2** | **`py`** | **i16 LE** | **锚点 Y** | **`:268`** |
| 12 | 4 | `csize` | u32 LE | 压缩字节数（`0` = 未压缩裸数据） | `:269` |

⇒ **也有**。位置比 WIL 后移 4 字节，因为块头前面多了 `marker + unused` 各 2 字节 —— **同一语义字段，不同容器布局**。

### 1.4 有偏移，那为什么没进 `Frame`？—— **解了、上层也落了，只是最后一跳没搬**

三段链路逐一核：

| 环节 | 是否带偏移 | 证据 |
|---|---|---|
| ① 二进制解析 | **带**：`FrameInfo.px / FrameInfo.py` | `wil_decoder.rs:40-58@412fe3e8`（字段声明 `:49-52`）；WIL 填值 `:208-209`；WZL 填值 `wzl_decoder.rs:267-268` |
| ② 图集 meta 落盘 | **带**：每帧 `anchor: [px, py]` | `meta.rs:27@412fe3e8`（`pub anchor: [i16; 2]`，注释「对应 C++ TDXTextureInfo.px/py」） |
| ③ `mir2_assets::Frame` | **不带**：只有 `width/height/rgba` | `frame.rs:10-17@412fe3e8(未入库)` |
| ④ `Frame` 的唯一生产点 | **漏搬**：只搬 3 个字段 | `wil_source.rs:191-196@412fe3e8(未入库)` |

`wil_source.rs:191-196` 原文（漏搬现场）：

```rust
match slot.lib.decode_frame(idx, &slot.palette) {
    Ok(f) => Some(Frame {
        width: f.width,
        height: f.height,
        rgba: f.rgba,          // ← f.info.px / f.info.py 就在这里，没搬
    }),
```

而 `DecodedFrame`（`wil_decoder.rs:78-85`）**本身带着 `info: FrameInfo`**，也就是说 `px/py` 到 `f.info.px` 只差一次字段访问。

**⚠ 一处需订正的表述**：`lighting.rs:56-59@412fe3e8(未入库)` 的模块文档写「这个偏移在当前数据链路上**不可得**」。
按本节实测，**数据本身完全可得**（解析层、meta 层都有），**不可得的只是 `Frame` 这一个结构没暴露它**。
⇒ 准确说法应是「**当前 API 未暴露**」，不是「数据链路上不可得」。这是**表述过强**，不是事实错误，但会误导后续判断（让人以为要重新解二进制）。建议改为「`Frame` 未暴露该字段，需扩结构」。

### 2.3 ⚠ 容器口径必须说清（否则会被误读成「官方读的是 .wil/.wzl」）

| 项 | 事实 | 出处 |
|---|---|---|

## 影响面：补上能精确多少 / 补不上最坏偏多少像素

### 5.1 偏差的**形态**：整张光罩平移，不是「光心单独偏」

官方与 `light_bounds` 的算式（`MapPreview.cs:27-28@901dbe2f` ↔ `lighting.rs:211-222@412fe3e8(未入库)`）：

```text
左上 = ( x*48 - posW/2 - 14 + offset.X ,  y*32 + 11 - posH/2 + offset.Y )
尺寸 = ( texW , texH )        ← 与 offset 无关
```

⇒ `offset` **只加到左上角、不改尺寸** ⇒ **整张光罩（含它的几何中心）平移 `(offset.X, offset.Y)`**。

所以「光心偏移」与「光罩错位」**不是两种可能，是同一件事的两种说法**：
- 看**光心相对格子的位置** ⇒ 偏 `(offset.X, offset.Y)`；
- 看**光罩覆盖范围** ⇒ 整体平移 `(offset.X, offset.Y)`；
- 看**光心相对光罩** ⇒ **不变**（仍在贴图几何中心，因为尺寸没动）。

⚠ 另一个**不是本次偏差**的既有错位（免得混算）：官方定位用 `lightSizes[index]`、贴图用 `lightSizes[index+1]`，两者不等 ⇒ 光罩中心**本来就**偏离格子中心 `(texW-posW)/2, (texH-posH)/2`（`light=9` 时为 `(+40, +30.5)` px）。这是官方故意保留的错位（`MapPreview.cs:24-25` 注释原文「Preserve that one-entry difference」），**与 `(0,0)` 近似无关**，补偏移时也不许"顺手修正"。
