## 三、已验收的关键能力（都有字节级或像素级证据）

### 3.1 地图格式
- **9 种格式全部可读可写**：Old12(12B) / Shanda14(14B) / Shanda2012(36B) / Wemade2010(15B,双档) / AntiHack(12B+XOR) / Mir3Wemade / Mir3Shanda / Heroes34 / CrystalCs(Type100 变长)
- **判别用"长度精确整除"而非标题字节** —— 实测 C# 的标题判别会**漏判 17 张**（14B 被当 12B 读花）、**误判 4 张**（12B 被当 14B 越界）
- **36B 是 14B + 22 字节尾区**，尾区**原样保留**（实测偏移 18/19/20/24 都有非零，不能假设恒零）

### 3.2 编辑内核
- **bit15 保留矩阵**：地表 `bk_img` 保留（低阻挡）/ 物体 `fr_img` 保留（高阻挡）/ 中层 `mid_img` 不保留
- **印章放置**：占用闸门（落点有物件 ⇒ 整枚拒绝，`PlacedStamps.cs:62-63`）+ 坐标重复闸门 + 粘贴路径不套闸门
- **选区/剪贴板**：闭区间语义、整格抓取、一次操作一步撤销、逐字节还原
- **保存**：tmp → sync_all → 读回核对 → rename → 尽力 fsync 目录（NTFS 目录刷不动，**如实打印**不假装）

### 3.3 渲染
- 三层落格与客户端**同源**（地表偶偶格 96×64、中层左上、物体底对齐）
- 多倍率 0.25/0.5/1/2：`One` 档与旧路径**逐字节相同**；流式 Box 与整幅 Box **逐字节相同**（FNV `52ed654a6ead95ec`），内存峰值 269.8 → 125.9 MiB

### 3.4 网页版
- `/api/tiles` 出图与离线 `render_0.png` **sha256 相同**（`5F122CFA…`）
- 前端四档缩放请求 `0.25 → 0.5 → 1 → 1`（200% 不请求 2×，会超限）；单块体积比 **14.7 倍**
- 移动端 375×812 实测：单栏 + 底部抽屉 + 触摸长按放置印章

## 七、过程中纠正过的重大误判（留档，防重犯）

| # | 原判断 | 实际 | 根因 |
|---|---|---|---|
| 1 | Type1 是 17B/格 | **15B** | `Bytes[offSet += 2]` 是"先加后取"，只加一次 |
| 2 | Type3 是 40B/格，C# 读不了真实 36B | **36B，C# 能读** | `ToInt16(Bytes, offset)` **不推进**，其字节落在跳过区内部 |
| 3 | `editable=false` 该覆盖 8 种格式 | **Old12 应可编辑** | 12 字节全具名、`unmodeled_fields` 空、856 张样本 0 差异；错判导致 1,051 张真实图挂假黄条（现降到 262） |
| 4 | 25% 缩放能省 37 倍流量 | **14.7 倍** | 37 是"单块像素数比"，没算"每屏要几块" |
| 5 | 印章放置没有占用闸门是"有意差异" | **是 P0 缺陷** | C# `CanPlaceStamp` 有 `HasForeground` 判据，会静默抹掉原有物件 |
| 6 | 「无汇报」= 零产出 | **错** | 断线的代理实际完成了工作，只是没发汇报 ⇒ **先查 mtime 再下结论** |
