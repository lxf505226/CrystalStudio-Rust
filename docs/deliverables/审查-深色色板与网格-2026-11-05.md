## A. 深色色板：41 个字段 vs 官方

### A.1 口径（为什么"官方深色值"≠ `App.axaml` 的字面值）

官方 `ThemeService.ApplyPalette(bool dark, Color accent, …)`（`ThemeService.Avalonia.cs:35-57`）**不是**"深色读 XAML、浅色另算"，而是每次调用都把 `Theme*` 资源**就地改写**：

1. 遍历所有 `Theme` 前缀键（`:39`），把 `"#" + key[5..]` 解析回颜色（`:41`；`ThemeED1C2028` 这类 8 位 ARGB 也能解析成功，同样进变换）；
2. 算亮度与"是否蓝键"（`:42-43`，蓝判据 `B-R > 35 && B-G > 12`）；
3. **深色下**：非蓝键**保持 XAML 字面值**（`:47` 的 `else if (!dark)` 不成立 ⇒ `color` 仍是 `original`）；
   **蓝键按 accent 重算**（`:46`）：`lum < 0.4 ⇒ Blend(#191D23, accent, 0.28)`，否则 `Blend(accent, White, 0.30)`；
4. 循环**之后**再覆盖（`:50-52`）：四个**命名刷** `Panel`/`Muted`/`Accent`/`Line`（取变换后的 `Theme*` 值）
   ＋ **`Theme6378DF = accent`** ＋ `OnAccent`（亮度 > 145 ? 黑 : 白）；
5. 三个命名刷**直接写死、不参与变换**：`CanvasBackground = Theme14171D`（`:53`）、
   `CanvasPaper = dark ? (31,37,43) : (239,242,245)`（`:54`）、**`CanvasGrid`**（`:55`）；
6. 默认 accent = `#8498FF`（`:32` 的平台 accent 兜底）。

⇒ 判"官方深色值"必须走**运行期结果**。本表逐项按此口径复算（蓝键/覆盖项在备注里写算式）。

### A.5 浅色侧交叉验证（用来**反证**官方源键）

## C. 缺陷清单（6 条，全部带行号）

> 按严重度排序。每条给：现象 → 证据 → 影响 → 建议改法。
> 建议里的 `rgba_pm(...)` 都是按本仓既有口径（**截断**，见 `theme.rs:358` 的 `selection_fill`）从官方 straight-alpha 值算出的预乘值，算式一并写出，可逐字节复算。

### D1（高）`grid_line` 两套板都不是官方值：官方有**专用** `CanvasGrid`，我们借了别的角色

- **现象**：深色 `#353E4C`（不透明）、浅色 `#D3D8DD`（不透明）。
- **证据**：`theme.rs:310-314`（深色，注释自称"取官方唯一的中性线档 `Theme353E4C`"）、`theme.rs:199-202`（浅色，注释明写"取 `checkbox_border` 的实测值 `#D3D8DD`"）。
  官方：`ThemeService.Avalonia.cs:55` `resources["CanvasGrid"] = dark ? ARGB(38,160,177,199) : ARGB(60,73,89,108)`；消费点 `MapViewport.cs:137` `new ScenePen(ThemeService.Brush("CanvasGrid"), 0.6)`。
  §A.5 的闭环还证明了浅色 `#D3D8DD` 其实是 `Theme586477`（**复选框边框**）的官方浅色变换 —— 即我们把复选框边框当成了网格线。
- **影响**：网格压在真实地图位图上。官方是 **≈15% 半透明蓝灰**（深色）/ **≈24% 半透明深灰**（浅色），我们是 **100% 不透明中性灰** ⇒ 深色下压图明显更重、且偏中性灰而非官方偏蓝；两套板都错，不是"只有深色没抄"。
- **建议**：改成官方半透明值（`egui::Color32` 是预乘存储，故用 `rgba_pm`）：
  - 深色 `rgba_pm(23, 26, 29, 38)`（算式 160×38/255=23.8→23、177×38/255=26.4→26、199×38/255=29.7→29）
  - 浅色 `rgba_pm(17, 20, 25, 60)`（73×60/255=17.2→17、89×60/255=20.9→20、108×60/255=25.4→25）
  - ⚠ 改完要确认 `theme.rs:461-463` 的 `assert_ne!` 仍成立（两板 alpha 不同 ⇒ 不等，成立）。

### D2（高）`accent_dark = #6378DF` 是 XAML 字面值；官方运行期把它**覆盖成 accent**

- **现象**：`theme.rs:299-300` `accent_dark: #6378DF`。
- **证据**：`ThemeService.Avalonia.cs:51` `resources["Theme6378DF"] = new ImmutableSolidColorBrush(accent);` —— 这行在变换循环（`:39-49`）**之后**执行，把蓝键公式算出的 `#A8B6FF` 也一并覆盖 ⇒ 深色下 `Theme6378DF` 恒等于 `accent`（默认 `#8498FF`）。`App.axaml:40` 的 `#6378DF` 只是**声明值**。
- **影响**：① 上屏值不是官方值；② 官方"深一档强调色"与 `accent` **同值**，我们却造了一个官方不存在的差档（页签下划线 / 1px 边框本该与强调色同色）；③ `accent` 与 `accent_dark` 在官方是同一个颜色，我们的 `Palette` 结构却假定它们必须不同。
- **测试覆盖不到**（**显式说明，避免误判"有测试就没事"**）：`theme.rs:461-463` 的 `assert_ne!` 只比对 **LIGHT 与 DARK 的同一字段**，既不校验 DARK 值有没有官方出处，也不校验 DARK 内部是否有重复值 ⇒ 即使把 `accent_dark` 改成官方运行期值 `#8498FF`，这条测试**仍然是绿的**。它挡的只是"深色漏抄一个字段"（`:404-407` 注释也这么写），挡不住"抄错来源"。
- **建议**：改成 `#8498FF`（或直接复用 `accent`），注释写明"官方 `:51` 覆盖 `Theme6378DF = accent` ⇒ 深色下两者同值"。

### D3（高）`status_dot` 官方有明确值 `ThemeD1AD77`，我们用了文字色

- **现象**：`theme.rs:339-340` `status_dot: #E5E9F0`（注释"官方: App.axaml:83 Window Foreground"）。
- **证据**：`MainWindow.axaml:81`：`<Ellipse x:Name="LibraryDot" Width="6" Height="6" Fill="{DynamicResource ThemeD1AD77}" …/>` —— 状态栏"资源库"圆点的官方色是 **`#D1AD77`**（金/琥珀档）。闭环：我们 `LIGHT.status_dot = #434D5A` 正是 `ThemeD1AD77` 的官方浅色变换（`lum=0.693 ≥ 0.4` ⇒ 固定 `(67,77,90)`）⇒ 浅色侧抄对了键，深色侧没跟着键走。
- **影响**：深色状态栏圆点从官方金色变成灰白，与旁边的 `Muted` 文字同色 ⇒ 圆点失去"状态指示"的视觉区分；同时也解释了为什么 `warn_banner_edge`（`#D1AD77`）看起来"孤立"——官方这个金色档本来就用于状态圆点。
- **建议**：`#D1AD77`。

### D4（高）`collision_low_mark` / `collision_high_mark` 被改成自造色；官方这两个是**主题无关常量**

- **现象**：深色 `#D69D92` / `#A8B6FF`（`theme.rs:334-338`，注释自称"映射是我选的"）。
- **证据**：`CollisionMarkers.cs:6-7`：
  `private static readonly Color First = Color.FromArgb(90, 240, 85, 105);`
  `private static readonly Color Second = Color.FromArgb(90, 65, 165, 245);`
  两者是 `static readonly`、**不经 `ThemeService`** ⇒ 深浅两套主题下都是这两个值。而我们 `LIGHT.collision_low_mark = #F05569`（= 240,85,105）、`LIGHT.collision_high_mark = #41A5F5`（= 65,165,245）**RGB 与官方逐字节相同** ⇒ 源键无疑，只是漏了 alpha=90，深色侧又被换掉。
- **影响**：深色下低/高位阻挡标记与官方颜色语义完全不同（官方：红/蓝各 **35% 半透明**；我们：粉灰/蓝紫**实色**）——阻挡标记是压在格子上的覆盖层，不透明会盖掉图块本身，这正好破坏"看图判断能不能走"的用途。
- **建议**：两套板**同值**改回官方：
  - 低 `rgba_pm(84, 30, 37, 90)`（240×90/255=84.7→84、85×90/255=30.0→30、105×90/255=37.1→37）
  - 高 `rgba_pm(22, 58, 86, 90)`（65×90/255=22.9→22、165×90/255=58.2→58、245×90/255=86.5→86）
  - ⚠ 两板同值会让 `theme.rs:461-463` 的 `assert_ne!` **红** ⇒ 必须把这两个字段加进 `theme.rs:410` 的 `same_ok` 白名单（与 `modal_scrim`/`accent_button_text` 同理），并在注释写"官方 `CollisionMarkers.cs:6-7` 与主题无关"。

### D5（中）两个"蓝键"抄了字面值（深色会被官方按 accent 重算），`selection_fill` 也是自造

- **现象**：`accent_soft` = `#2B355A`（`theme.rs:301-302`）、`menu_popup_hover` = `#2B355A`（`theme.rs:368-369`）；`selection_fill` = `rgba_pm(20,23,40,40)`（`theme.rs:357-358`）。
- **证据**：`#2B355A` 满足官方蓝判据（`B-R = 90-43 = 47 > 35`、`B-G = 90-53 = 37 > 12`，`ThemeService.Avalonia.cs:43`），亮度 `= 0.210 < 0.4` ⇒ 走 `:46` 第一支 `Blend(#191D23, accent, 0.28)` = `(54.96, 63.44, 96.6)` 截断 = **`#363F60`**。
  `selection_fill` 官方：`MapViewport.cs:295` `new ImmutableSolidColorBrush(Color.FromArgb(30, 110, 150, 255))` —— **固定蓝**，不是 accent 派生，alpha 也是 30 不是 40。
- **影响**：深色下"选中态"底色偏紫蓝（`#2B355A`）而非官方的灰蓝（`#363F60`）；选区填充与官方色/透明度都不同（官方 12%/蓝，我们 16%/accent 蓝）。
- **建议**：`accent_soft` 与 `menu_popup_hover` 改 `#363F60`；`selection_fill` 改 `rgba_pm(12, 17, 30, 30)`（110×30/255=12.9→12、150×30/255=17.6→17、255×30/255=30.0→30）。

### D6（中低）网格**不裁地图边界**：格线会画到图外的空白区（官方裁）

- **现象**：地图小于画布（或缩得较小）时，地图边界之外的空白区里出现格线。
- **证据**：`grid.rs:98` 取 `view.visible_cells(canvas)`，`:106` `for i in x0..=x0 + w as i32`、`:118` `for j in y0..=y0 + h as i32` —— 范围完全由视口决定；而 `canvas_view.rs:236-249` 的 `visible_cells` **签名里没有地图尺寸**（只有 `pan/scale/canvas`），`x0/y0` 在平移出图时会为负。
  官方对照：`MapViewport.Presentation.cs:37-39`
  `int x1 = Math.Min(Document.Width, (int)((ActualWidth - origin.X) / Zoom / 48) + 1);`
  `int y1 = Math.Min(Document.Height, …);` —— 枚举范围被 `Math.Min(地图尺寸, …)` 夹到图内。
- **可复现算术**（不用跑程序）：64×48 的图、`scale=0.5`、画布 987×815 ⇒ 图高 `48×32×0.5 = 768 px < 815 px` ⇒ 底部约 **47 px** 空白区出现横线；竖线同理（`grid.rs:146` 竖线高度直接取 `canvas.height()`、`:153` 横线宽度直接取 `canvas.width()`，都不看地图多大）。
- **影响**：纯视觉，且只在"图比画布小"时出现（正常 1× 看大图不会触发）；但它会让"像素差只落在格线"的截图验收在空白区多出线条，属于验收口径的噪声。
- **建议**：**只改 `grid::lines`**，给它加地图尺寸参数（或 `Option<(u16,u16)>`），把 `x0..=x0+w` 夹到 `0..=map_w`、`y0..=y0+h` 夹到 `0..=map_h`。
  ⚠ **不要改 `canvas_view::visible_cells` 的语义** —— 它同时被 `ensure()`（`canvas_view.rs:292`，重渲窗口）和小地图共用，改它会波及重渲缓存键与验收基线。
