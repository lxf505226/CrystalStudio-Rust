## 3. 缓存正确性（`tiles.js` 缓存键是否含全部出图参数）

### 3.1 ✅ 缓存键字面上包含全部 6 个请求参数

`tiles.js:28-31`：

```js
function keyOf(p) {
  return p.x + ',' + p.y + ',' + p.w + ',' + p.h + ',' + (p.scale || '1') +
    ',' + p.layers + ',' + (p.collision || 'none');
}
```

对照后端 `tiles.rs:142-269`：`/api/tiles` 的输入**只有** `x / y / w / h / scale / layers / collision` 七个（前四个进 `Viewport`，后三个进 `LayerMask` / `CollisionOverlay` / `RenderScale`），**没有第八个影响出图的参数**。⇒ 就"参数遗漏"这条字面判据而言，**键是完整的**，不会出现"同键不同图"。

`scale` 单独列出（`tiles.js:4-6` 注释）确实必要：`ME.tileScaleFor` 四档里 100% 与 200% 都请求 `'1'`，但 25%/50% 各是不同尺寸的图（`tiles.rs:447-457` 的 `round(w*48*s) × round(h*32*s)`），不含 `scale` 必然串图。

### 3.2 🔴 缓存键缺的是「**图身份 / 世代**」，且 `clear()` 不取消在途请求 ⇒ 换图串图

键里没有"这是哪张地图"的标识，全靠 `app.js:131` 的 `ME.tiles.clear()` 兜底。但 `tiles.js:176-187` 的 `clear()` 只清 `cache` 与 `pending`，**没有任何世代号 / AbortController**；而 `load()` 的闭包（`tiles.js:57-90`）在请求返回后**无条件** `put(k, …)`：

```js
function load(k, p) {
  if (pending[k]) return;
  pending[k] = true;
  ME.api.fetchTile(p).then(…).then(function (got) {
    delete pending[k];
    put(k, { state:'ok', bitmap: got.bitmap, … });   // ← 不校验"我还是不是当前那张图"
  })
```

⇒ 时序：开 A 图 → 瓦片请求在途 → 立刻开 B 图 → `applyMap` 调 `clear()` → **A 图的 PNG 回来，按同一个键写进 B 图的缓存** → 画布上 B 图的位置显示 A 图的地块。这与任务里担心的"漏参数导致串图"是同一后果，只是漏的那个"参数"是**地图身份**。

同样的竞态也存在于 `invalidate()`（`tiles.js:151-165`）：作废缓存时在途请求不会被取消，回来照样落进缓存 ⇒ 撤销/放印章后可能重新出现改动前的旧块。

### 3.3 🔴 `Fill` 之后只失效锚点那一块 ⇒ 大片陈旧

两端拼起来看：

- 后端：`json.rs:179` 把 `Command::Fill` 归进 `touched_cell()` 的 `Some((x, y))`；`edit.rs:99-105` 据此发 `Rerender { x, y, w: 1, h: 1 }`（`span = u16::from(cell.is_some())`）。
- 前端：`app.js:412-414` `ME.tiles.invalidate(p)` → `tiles.js:152` 因 `w/h` 非 0 走"只删相交块"分支 ⇒ **只删掉含 (x,y) 的那一个 16×16 块**。
- 但 `Fill` 是 **BFS 连通填充**（`cmd.rs:140`「填充（BFS 连通块，整次填充 = 一步撤销）」），回执 note 是「填充 N 格」（`cmd.rs:289`），N 可以是整张图。
- `app.js:298-301` 的 `REGION_CMDS` 兜底表里有 `PlaceStamp` / `PasteSelection` / `DeleteSelection` / `CutSelection` / `FillSelection`，**唯独没有 `Fill`**。

⇒ 用填充工具点一下，屏幕上**除锚点那一块外全部显示填充前的旧图**，直到滚出视野再滚回来或缓存被挤掉。这是"缓存正确性"里最实打实的一条。

### 3.4 🟠 `Paint` / `Erase` 的笔刷足迹跨块时，邻块不失效

- 笔刷足迹 = 以 `(x,y)` 为中心的 N×N（`brush.rs:326-338`，`radius = n/2`），缺省 `n = 3`（`brush.rs:294` `BRUSH_DEFAULT = 3`）⇒ 覆盖 `x-1..x+1`。
- 块 = 16 格（`config.js:52` `ME.CHUNK = 16`）。
- 在 `x ≡ 0` 或 `x ≡ 15 (mod 16)` 处落笔，足迹必然跨进相邻块，而 `Rerender` 只带 `w=h=1`（同 3.3）⇒ **每 16 列里有 2 列的落笔会留下一条 1 格宽的陈旧边**。
- 若将来接上 `SetBrushSize`（`json.rs:259-263`，上限 31 ⇒ `radius = 15`），一条笔横跨 2～3 个块，问题会放大到"半屏不刷新"。

### 3.5 🟠 `tiles.js` 把"失败"计成"命中"，且持续失败每 3 秒重试一次

`tiles.js:97-112`：命中 `state:'missing' && soft` 且未满 3 s 时，走 `stats.hits++` 并 `return hit`。⇒ 失败次数被记成命中，`stats` 不可信。满 3 s 后 `cache.delete(k)` 再 `load()`，所以只要该块还在视野内且后端一直 503，就会**每块每 3 秒重发一次**请求；而 `ui.js:447-452` 只对"同一句原因"提示一次，`stats.failed` 也不上状态栏 ⇒ 用户看到的是"画布一直斜纹，没有任何持续失败提示"。

## 7. 总体判断

**契约层面是干净的，可用性问题集中在"缓存失效粒度"和"移动端手势"两处，而移动端目前不能用于实际编辑。**

- **契约（第 1 类）：一致。** 前端实际发出的 13 类命令、7 个查询参数、9 个错误码、11 个 `/api/map` 字段、5 个 `/api/edit` 回执字段，与 `json.rs` 的 `name()`/`parse()`、`tiles.rs` 的参数解析、`error.rs` 的码表**逐项对得上**；没有"前端发了后端不认"的一条。唯一"后端返了前端读不到"是 `X-Render-Scale`（被 CORS 挡住，且被兜底伪装成正常）。反向缺口 3 条（`SetBrushSize` 零调用、`SetBrushFromPalette` 待接入、`Save` 走另一条端点），均已在代码注释里如实登记，不算欺骗。
- **静默失败（第 2 类）：`fetch` 层做得比多数项目好**（三处全查 `resp.ok`，非 JSON 的 200 判 `bad_response`），问题全在**上层语义**：`saved` 不查、WS 报文静默丢、回执解析失败静默保留本地值。这三处都不会立刻出错，但都会在"契约漂移"那天变成无声故障。
- **缓存（第 3 类）：键的字面参数是完整的，缺的是"图身份/世代"。** 加上 `Fill` 只失效一块、笔刷足迹跨块不失效，这一类的真实症状不是"参数漏了"，而是"该失效的没失效"。
- **移动端（第 4 类）：断点与布局做得细（连 2026-11-05 那次"印章行点不动"都留了实测记录并修对），但手势层是照桌面写的。** 单指不能平移、捏合必误落笔、长按无定义、无未保存指示 —— 这四条叠加起来，**手机上不适合真正编辑地图**，只适合查看。
- **无框架纪律（第 5 类）：满分执行。** 关键词 0 命中、零外部依赖、13 个代码文件全 ≤600 行（`app.css` 598 已接近上限）。

**一句话：桌面端契约与实现都站得住，桌面可用；移动端"能打开、能看、不能安全地改"；`Fill` 与换图两处缓存失效是桌面端也会遇到的真实缺陷。**
