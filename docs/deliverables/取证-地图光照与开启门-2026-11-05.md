### 1.2 它到底改变什么（消费点，不是猜）

**结论：三者都不是。** 既不是给每格像素乘亮度系数，也不是换调色板，更不是改 `Light` 字节的解释。官方做法是：

> **在精灵场景之上盖一张全屏黑色遮罩（alpha = 全局环境光缺口），再用「光罩贴图」把该处的 alpha 减掉（= 加光）。**

证据链（4 个消费点，全部读完）：

| # | 位置 | 关键代码 | 作用 |
|---|---|---|---|
| 1 | `MapViewport.cs:89` | `public bool DarknessVisible => Lighting != MapLighting.Day;` | **白天 = 完全不画遮罩**（唯一「关」的形态） |
| 2 | `MapViewport.Presentation.cs:34-35` | `if (DarknessVisible && ActualWidth > 0 && ActualHeight > 0) dc.DrawImage(DarknessMask(), new Rect(0, 0, ActualWidth, ActualHeight));` | 遮罩铺满**整个视口**（屏幕坐标，非地图坐标） |
| 3 | `MapViewport.Presentation.cs:70` | `byte darkness = Lighting switch { MapLighting.DawnDusk => 205, MapLighting.Day => 0, _ => 255 };` | **三档的全部差异就在这一个字节** |
| 4 | `MapViewport.Presentation.cs:87-93` | `pixels[i] = (byte)Math.Max(0, pixels[i] - texture.Pixels[ty * texture.Width + tx]);` | 逐格光源：从遮罩 alpha 里**减去**光罩强度 |

原始注释（`MapViewport.Presentation.cs:68-69`，逐字）：

```csharp
// Crystal's DrawLights multiplies the scene by ambient RGB plus additive map lights:
// dawn/evening = 50, day = 255, standard night = 0.
```

### 1.3 具体公式/系数

#### A. 全局环境光（整幅一层）

| 档位 | 环境光 ambient（注释值） | 遮罩 alpha = `255 - ambient` | 代码字面量 |
|---|---|---|---|
| 黎明/黄昏 DawnDusk | **50** | **205** | `Presentation.cs:70` `DawnDusk => 205` |
| 白天 Day | **255** | **0** | 同左 `Day => 0` |
| 夜晚 Night | **0** | **255** | 同左 `_ => 255`（默认分支 = Night） |

三者与注释 **自洽可验**：`255-50=205`、`255-255=0`、`255-0=255` ⇒ 两条独立证据（注释 + 字面量）互证，**不是编的**。

#### B. 按格 `light` 字节的进一步调制（有，且是 1–9 档）

| 项 | 规则 | 出处 |
|---|---|---|
| 生效条件 | `cell.Light is > 0 and < 10` **且** 该格有前景图（`Foreground.Library >= 0` 且 `(Image & 0x7FFF) != 0`） | `MapPreview.cs:14-15` `EmitsLight` |
| 只在物件层可见时叠加 | `if (VisibleLayers[2]) foreach (var (x, y, cell) in metadataCells)` | `MapViewport.Presentation.cs:73` |
| 尺寸表 | 11 项：`(125,95) (205,156) (285,217) (365,277) (445,338) (525,399) (605,460) (685,521) (765,581) (845,642) (925,703)` | `MapPreview.cs:17-19` |
| 下标 | `index = Math.Min(light * 3, 9)` | `MapPreview.cs:23` |
| 定位尺寸 vs 贴图尺寸 | **定位用 `lightSizes[index]`，贴图用 `lightSizes[index+1]`**（官方故意保留这一格错位） | `MapPreview.cs:26` |
| 贴图宽 | `light == 1 ⇒ 445`、`light == 2 ⇒ 685`、**其它（3–9）⇒ 925** | `MapPreview.cs:34` |
| 左上角（世界坐标，格内 48×32） | `x*48 - posW/2 - 14 + offset.X`，`y*32 + 11 - posH/2 + offset.Y` | `MapPreview.cs:27-28` |
| `offset` 来源 | 前景帧精灵自身的 `sprite.X/sprite.Y`（取 `(front.Image & 0x7FFF) - 1` 那一帧） | `Presentation.cs:76-79` |
| 强度来源 | 光罩 PNG 的 **R 通道**（Premultiplied Pbgra32 ⇒ R = SourceAlpha×colour） | `MapPreview.cs:40-43` |
| 合成 | `alpha = max(0, alpha - intensity[tx,ty])` | `Presentation.cs:91-92` |

### 1.4 作用在哪一层

| 问题 | 答案 | 证据 |
|---|---|---|
| 遮罩盖几层 | **地表/中层/表层三层全盖**（三层都在同一个 `mapScene` 里按 `for (int layer = 0; layer < 3; layer++)` 画完，遮罩画在另一个更上层的 scene） | `MapViewport.cs:246`；`MapViewport.Scene.cs:25-26` + `:36-37` |
| 层级顺序怎么保证 | `AddSceneLayer` 是 `VisualChildren.Add` **追加**，后加的后绘 ⇒ `mapSurface → wallSurface → presentationSurface → interactionSurface` | `EditorWindow.cs:130-134`；`MapViewport.Scene.cs:25-26` |
| 地图外会不会变暗 | **不会**，遮罩被裁在地图矩形内：`dc.PushClip(new RectangleGeometry(map))`，`map = (origin, W*48*Zoom, H*32*Zoom)` | `Presentation.cs:31-32` |
| 光源从哪层取 | 只从**表层/物件层**的格取（要求有前景图），且要物件层可见 | `MapPreview.cs:14-15`；`Presentation.cs:73` |
| 灯光格/门格标记是否被压暗 | **不被压暗**——黄/青标记画在遮罩**之后** | `Presentation.cs:43-50`（在 `:34-35` 之后） |
| 缩放档 | 全档生效（`DrawPresentation` 在 `UpdateMapScene` 里无条件调用，遮罩按屏幕坐标画，与 `Zoom` 无关） | `MapViewport.Scene.cs:37` |

### 1.5 有没有开关

**没有独立的「启用光照」开关。** 三档互斥单选，**「白天」这一档本身就等于关**：

- `DarknessVisible => Lighting != MapLighting.Day`（`MapViewport.cs:89`）⇒ 白天连遮罩函数都不调用（`Presentation.cs:34` 的短路条件）；
- 即使硬画，白天的 `darkness = 0`（`Presentation.cs:70`），全透明，像素级无差别；
- 所以**不存在「调制系数 = 1」的分支**，只有「不画」。

> 口径提醒：这跟「系数 1」在像素上等价，但**代码路径不同**（少一次全屏 alpha 合成）——实现时照「白天跳过」写即可，不必造一个恒等系数。

### 1.7 能不能做

> **现在就能做。**

理由：三档常量（50/255/0 → 205/0/255）、11 项尺寸表、`light*3` 下标规则、1/2/其它 三档贴图宽、`+11/-14` 定位偏移、`max(0, alpha-intensity)` 合成式，**全部有官方源码字面量 + 注释双证据**；三张光罩 PNG 在仓内可直接复用；`light` 字节本仓已有真值（`mir2-map/src/cell.rs:195`）。**唯一需要「造」的东西为零**。

#### B. 官方编辑器（菜单的实际行为）— `MapPreview.cs:6-10`

```csharp
// Crystal client: GameScene.DrawObjects/DrawLights and DXManager.CreateLights.
internal static int FrontImage(Cell cell, Front front, bool doorsOpen)
{
    int image = (front.Image & 0x7FFF) - 1;
    return image < 0 ? image : image + (doorsOpen && (cell.Door & 0x7F) != 0 ? cell.DoorOffset : 0);
}
```

#### C. 两者差异（必须显式登记，不许含糊）

| 维度 | 官方客户端 | 官方编辑器 | 影响 |
|---|---|---|---|
| 触发条件 | `(door_offset & 0x80) != 0` **且** `(door_index & 0x7F) > 0` | `doorsOpen` **且** `(door & 0x7F) != 0` | 客户端看「运行期开合位」，编辑器是「强制全部开启」的模拟 ⇒ 语义上等价 |
| 偏移取值 | `door_offset & 0x7F`（**掩码**） | `cell.DoorOffset`（**整字节，未掩码**） | **实测有 1,229 格真实门格的文件值已带 0x80**（§2.4⑥）⇒ 编辑器口径在这些格上会 `+128+low` 画错帧。**移植按客户端掩码** |

> **原判断**：「所有 0x80 置位样本都落在 `y=0` 填充行，真实门格一个都没置位，故编辑器不掩码也无害」——**该判断是错的**。

> **改法**：结论改为「必须掩码」，并把「不掩码也无害」的说法从 §2.3、§2.6 一并删掉。

### 2.6 能不能做

> **现在就能做。**

- 公式：客户端 `GameScene.cpp:3328-3388` 与编辑器 `MapPreview.cs:6-10` 两份原文，差异已列清；
- 数据：`door_index`/`door_offset` 本仓已有（`mir2-map/src/cell.rs:185-187`），全量 1097 张图里 **170 张**含门格（共 3,927 格）；
- 帧：开门帧实测存在且与闭门帧同尺寸成对（§2.4 ⑤），`Objects_atlas_meta.json` 可直接查；
- 影响面：只需给表层取帧加一个 `+ (door_offset & 0x7F)` 分支 + 一个布尔状态 + 把该状态并进渲染缓存键（对应官方 `DetailState`/`SceneState` 的做法）。

**必须按客户端口径写，不能照抄编辑器的整字节加法**（这不是「可选项」，是数据实测结论）：
- 客户端：`if (door_offset & 0x80) != 0 && (door_index & 0x7F) > 0 → frame += door_offset & 0x7F`
- 编辑器：`if (door & 0x7F) != 0 → frame += door_offset`（整字节）
- 实测有 **1,229 格**真实门格的 `door_offset` 文件值已带 `0x80`（§2.4⑥），照编辑器写法会多加 128 ⇒ 错帧。
- 若要做「预览全部开启」，把客户端条件里的 `door_offset & 0x80` 换成「开关打开」即可，**偏移仍必须 `& 0x7F`**：

```
frame = (fr_img & 0x7FFF) - 1
if (doors_open_toggle && (door_index & 0x7F) != 0)
    frame += (door_offset & 0x7F)
```

## 总结

### 结论表

| 菜单项 | 官方机制（一句话） | 关键常量/公式 | 依据强度 | 判断 |
|---|---|---|---|---|
| 地图光照（3 档） | 全屏黑遮罩 `alpha=255-环境光`，再逐格用光罩贴图**减 alpha** 加光 | 环境光 `50/255/0` ⇒ 遮罩 `205/0/255`；光罩 `light*3` 索引 11 项尺寸表；`1/2/其它→445/685/925` 宽；`alpha=max(0, alpha-intensity)` | 常量有**代码字面量 + 注释**双证且自洽；光罩 PNG 实测在库 | **现在就能做** |
| 开启门（复选） | 只把门的**前景帧号**加一个偏移，不改阻挡、不改数据 | `frame = (fr_img & 0x7FFF) - 1 + (door_offset & 0x7F)`（门索引非 0 时） | 客户端 `GameScene.cpp` + 编辑器 `MapPreview.cs` 两份源码 + 真实门格 + 真实帧级验证 | **现在就能做** |

### 该不该做（按本仓铁律逐条对）

铁律是「原版不可得 ⇒ 自定值必须标注；宁可不做也不许编」。这两个项**恰恰不属于「原版不可得」**：

1. **两个功能的每一个数字都能指到源码行**：光照的 `50/255/0`（`MapViewport.Presentation.cs:68-70`）、`205/0/255`、`light*3`、11 项尺寸表、`445/685/925`；门帧的 `& 0x7FFF`、`& 0x7F`、`-1`、门索引判据（`MapPreview.cs:6-10` + `GameScene.cpp:3328-3388`）。
2. **两个功能的数据都在仓内**：光罩三张 PNG（66,669 / 127,337 / 198,508 B）；`door_index`/`door_offset` 字段 + 1097 张图里 170 张含门（3,927 格）+ `Objects` 库里成对的开门帧（`1747..1751` vs `1753..1757`）。
3. **需要「自定」的项为零**：没有任何一处要我自己拍一个系数、阈值或帧表。

⇒ **两个都该做，而且应该做**——现在把它们灰显的理由本身是错的：
- `ui_text.rs:302` 说地图光照「要按 Crystal 光照表**逐格改色**」→ 实际是**全屏遮罩 + 光罩减 alpha**，不是逐格改色；
- `ui_text.rs:304` 说开启门「**渲染库没有门态数据**」→ 门态数据在 `mir2-map/src/cell.rs:185-187`，缺的是渲染实现。

**反过来，什么情况下必须不做/必须标注**（给后续接手者的红线）：

| 情形 | 处置 |
|---|---|
| 想「自己生成」光罩贴图（不复用仓内三张 PNG） | 属**原版参数不可得**（生成脚本全仓无）⇒ 必须在代码注释与文档标「原版不可得 ⇒ 自定值」并列待回源项，**不得静默自造衰减曲线** |
| 想按「感觉更暗/更亮」微调 50/255/0 | **禁止**。这三个数是官方常量，改了就是改原版 |
| 想给「开启门」加动画过渡（淡入淡出） | **禁止**。官方是**瞬时换帧**（`sceneDirty=true` 重建），无过渡；加过渡 = 造功能 |
| 想让「开启门」顺带改阻挡 | **禁止**。编辑器该项纯视觉（`MapPreview.cs:9` 只算帧号）；客户端阻挡另有 `map_loader.gd:313-317`，两者不许混 |
